How the image tools work

A practical explanation of the processing method, verification steps and limits.

From your file to a download

  1. You grant the page access to the files you select or drop.
  2. The browser decodes each image locally and draws it to a canvas, optionally resizing it.
  3. The browser encodes a WebP, JPEG or PNG blob. The tool checks that the returned format matches the request.
  4. A temporary local URL lets you save the file. ZIP downloads package the converted files locally.

The conversion script is served as readable JavaScript. It contains no fetch, XMLHttpRequest or image-upload call.

How to verify local processing

  1. Open an image tool, wait for the page to load, then open your browser's developer tools.
  2. In the Network panel, clear existing entries. Select a non-sensitive image and convert it.
  3. Check that the image bytes are not sent in an upload request. Hosting analytics or security requests may still appear.
  4. Disable networking after the page and script load. Select another image and convert it in the same tab.

Quality, transparency and color

WebP and JPG output use the browser's lossy encoder. A quality value of 100 is not a guaranteed lossless WebP mode. PNG is a lossless encoding of the pixels produced by browser decoding and any resizing; it cannot reverse earlier compression.

PNG and WebP retain alpha. JPG composites transparent pixels over white. Source metadata and profiles are not deliberately copied; color and orientation can depend on browser decoding. Check color-sensitive work in your intended application.

Limits and unsupported formats

  • Inputs: PNG, JPG/JPEG and WebP only. HEIC, AVIF, GIF, SVG and PDF are not supported by this tool.
  • Maximum 20 files per batch, 25 MB each, 100 MB combined input.
  • Maximum decoded dimensions: 16,383 pixels per side and 24 million pixels. Oversized images are rejected rather than silently reduced.
  • Maximum generated file: 50 MB; combined output: 150 MB. A smaller batch may be needed on a phone.
  • Animations become a single still frame; animation timing and extra frames are not retained.
  • Browser memory can run out below these limits. Errors are shown per file so other files can still finish.

Evaluate the result before replacing an original

Compare size, dimensions, transparency and visual details. The reported percentage is based on your actual input and output bytes, not a published benchmark or a promise. Keep originals and avoid repeated lossy conversion.
